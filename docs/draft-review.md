# Native draft review

The next local [publishing milestone](publishing-management.md) moves historical
Publish date into Settings and adds a separate Publish/Schedule dialog, scheduled
status and cancellation. That layout supersedes the original main-form date and
action descriptions below. It requires its own migrations/grants and activation.

Implemented local slice, 2026-10-26. This is a small Go-rendered review page for one configured operator and publication per process. It does not implement Ghost Admin, Ghost staff/session APIs, account creation, MFA, taxonomy management or Ghost staff management.

## Handoff and behavior

`/ghost/posts/` is the authenticated posts list for the configured publication: title, draft/published status, last-updated date, and editor links, 20 per page. It includes drafts only after browser authentication and never renders article bodies. Search matches title/slug; status filters select drafts, published records or Trash. The Type control switches between posts and pages while preserving publication isolation. Pagination uses bounded page numbers; empty and unavailable states are explicit. Successful login without a post-specific return URL opens this list. `/ghost/` navigates there, while preserving the measured iA fragment handoff below; a standard Posts link works without JavaScript. The editor includes a Posts link back to the list.

Published articles show **Save changes**, which immediately updates the published revision; there is no separate unpublished edit or Update approval. Drafts show **Save draft** and **Publish**. Browsing the list and opening editors never writes posts or enqueues publishing events.

New post/page opens a small title form. Only Create draft writes a record. A session-bound signed creation ID makes retrying the same submitted form open the saved draft instead of duplicating it. Post settings contains the unique URL slug and publication time explicitly in UTC. Backdating changes the recorded publication time; future timestamps are rejected because no durable scheduler is implemented. Omitted metadata preserves history; clearing an existing publication time or sending published_at:null cannot erase that date. Slug edits preserve ID/UUID and require confirmation when previously published: this version does not create old-slug redirects, and the warning is explicit. Website redirect and cache handling must be integrated before claiming old links are preserved.

The management/session code requires migrations11–12 and the narrow runtime grants below before release; no deployment or content migration is implied by source availability.

Actual iA Writer 8.0.9 opens `/ghost/#/editor/post/<24-hex-post-id>/` after accepting a new draft. The `/ghost/` landing page contains no draft data; a strict fragment parser navigates to `/ghost/posts/<id>/`. That server route requires a separate authenticated browser session before querying the publication-scoped store. Knowing a post ID or UUID grants no access. Integration JWTs are never accepted as browser sessions.

The body is one bordered editor. Its header holds a compact **Rich text | HTML | Markdown** control and, in Rich text, the formatting toolbar: bold, italic, underline, strikethrough, inline code, link, H2/H3, bulleted and numbered lists, quote, code block, divider, image URL, table (with row/column/header/delete controls inside a table), undo and redo. There is no separate preview, stylesheet import, redundant heading, caption or shortcut text. Rich text is self-hosted Tiptap 3 on ProseMirror; see [the editor README](../internal/review/editor/README.md) and [ADR 0010](adr/0010-review-editor-engine.md).

The HTML source is authoritative and is the only submitted body field. A mode writes to it only after an edit in that mode: switching modes, or editing and undoing back, preserves the original HTML byte for byte. Before Rich text or Markdown shows a source, the editor compares canonical forms of the source and its conversion. Anything the conversion would drop (elements, attributes or text) is listed, and the author must explicitly convert; viewing a lossy conversion still changes nothing until an edit. Pasted HTML passes through the editor schema, so scripts, styles, classes, event handlers and unsafe URLs are not kept. Editor output stays inside the server's safe HTML profile. External resources remain blocked by CSP. Only the chosen mode name enters localStorage, never content.

Saving preserves the existing draft/published state. Publishing is explicit, uses optimistic concurrency and the existing transactional revision/outbox service, and makes the post eligible for the public Content API. Unpublish requires explicit confirmation and preserves the original publication date and content. Move to Trash is a confirmed, recoverable withdrawal; revisions, media references, ID and UUID remain intact. Restore returns to draft, never automatically republishes. Permanent deletion is not exposed. No personal-website route is added.

Each form carries the last-read millisecond `updated_at`. Stale writes return 409 and retain the submitted title/body and old token; the user must open the latest saved version and merge. Validation and database errors also retain submitted text. With JavaScript enabled, network errors and expired sessions leave the current form intact and explain that a lost acknowledgment may hide a completed save. No draft content enters localStorage. Native form submission remains available without JavaScript, but network/session interruption recovery is then browser-dependent. Keyboard focus styles, associated labels, explicit button labels, status/alert announcements and labeled HTML/rich-text editing regions are included.

## Explicit configuration

Browser review is disabled unless all three are supplied:

- `CONTENT_REVIEW_ORIGIN`: exact externally visible root origin, HTTPS except local loopback HTTP testing. Do not put the public website's base path here.
- `CONTENT_REVIEW_USERNAME`: separately configured operator name (letters, digits, period, underscore, hyphen; at most 64 characters).
- `CONTENT_REVIEW_PASSWORD_HASH`: operator-supplied digest generated by `content hash-password` from piped input supplied by a password manager/protected file. Never put the password in command arguments, repository files or logs. There is no default account/password and no unauthenticated setup endpoint.

Public attribution is separate from login. For iA new-draft compatibility, configure `CONTENT_AUTHOR_ID` (stable 24 lowercase hex characters), `CONTENT_AUTHOR_NAME` and `CONTENT_AUTHOR_SLUG` together. New posts snapshot that public author in immutable revision metadata. Updates preserve the snapshot; changing configuration does not reattribute existing records. Legacy records remain unattributed. No role, email, staff credential or permission is fabricated. These fields do not change the ActivityPub event contract.

## Security and operational limits

Passwords use standard-library PBKDF2-HMAC-SHA256 with a random 16-byte salt, 600,000 iterations and a 32-byte derived key; stored parameters are bounded on parsing. This local implementation supersedes the earlier Argon2id proposal for this single-operator slice; it makes no FIPS claim. The work factor follows the [OWASP PBKDF2 guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). Argon2id remains a possible future versioned hash format rather than an unimplemented claim.

Production browser sessions use the existing PostgreSQL schema. Only SHA-256 digests of opaque 256-bit cookie values are stored; CSRF tokens are derived independently from the secret cookie with domain separation and are never stored. Session scope binds publication, operator and the configured password digest. Test-only in-memory storage remains available when no session backend is supplied. Pre-login sessions expire after 10 minutes; successful login rotates the ID and expires after eight hours. Cookies are host-only, HttpOnly, SameSite=Strict, Path=/ghost/, and Secure on HTTPS. Every mutation requires exact Origin plus CSRF token. Logout deletes the session for every instance. Restarting retains database-backed sessions; changing operator/password configuration invalidates the old scope. The first transition from the legacy in-memory implementation requires one sign-in, because old process-memory sessions cannot be safely transferred. Five login attempts per source IP per 15 minutes, four concurrent password checks and bounded session/attempt maps limit local abuse. Forwarded IP headers are deliberately not trusted; behind a proxy the rate limit may aggregate clients. Login-attempt throttling is still per process; this release retains the single-replica deployment and does not claim shared throttling. Staff roles, account recovery and MFA are not implemented.

Runtime needs SELECT, INSERT and DELETE on its own `browser_sessions` table and UPDATE(trashed_at) on its existing posts table, in addition to existing post/media permissions. No session-row UPDATE, post DELETE, schema ownership or cross-module access is required. Migration/runtime credentials remain separate. Session capacity is bounded and writes serialize within the module/schema/scope; expiry is enforced at read time and expired rows are cleaned during issuance. The runtime refuses startup when its configured persistent backend is unavailable; there is no silent downgrade to memory.

Responses are no-store, same-origin referrer policy, nosniff and frame-denied, with a nonce CSP. The separate preview/frame was removed. The editor bundle loads from a content-addressed, nonce-bound `/ghost/assets/` script; it contains no private data and is served without a session. Tiptap's style injection is disabled, so the CSP needs no `unsafe-inline` or `unsafe-eval`. The editor schema and the unchanged server HTML validator protect editing boundaries. HTML input still follows the safe HTML profile; disallowed input is rejected rather than silently rewritten. Escaping-only differences, such as a raw apostrophe the sanitizer would write as `&#39;`, are accepted and the original bytes are stored. Arbitrary embeds/external preview resources are outside this slice. No login/request bodies, passwords, Authorization values or cookies are logged by the service or diagnostic tool.

Production requires an approved operator identity/password setup, TLS/reverse-proxy configuration, deployment ACLs, recovery policy and an explicit decision on the single-operator/process limit. None was provisioned here. Synthetic test credentials must never be reused for deployment.

## Evidence

`internal/review/server_test.go` checks authentication, rotation/expiry/logout, CSRF/Origin, cross-publication access, malicious HTML, throttling, safe redirects, conflict/error preservation and explicit publish. `storage/postgres/review_test.go` runs actual HTTP sessions against restricted real PostgreSQL: create through the observed iA route, private review, save, stale conflict, cross-publication denial, publish, public Content read, three immutable revisions and one atomic publication intent, zero delivery enrollment. Real-app completion is tracked separately in [the iA checkpoint](ia-writer-local-checkpoint.md).

Safari form verification exposed a policy interaction: `Referrer-Policy: no-referrer` makes native form POST Origin null, so the strict origin check correctly rejected login. The corrected policy is `same-origin`: native same-origin forms retain their origin, cross-origin referrers remain suppressed, and missing/null/foreign Origin values still fail. See [MDN's documented Origin effect](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header). This fixes the page policy rather than accepting null origins or removing CSRF protection.

## Private images and browser evidence

Authenticated `/ghost/images/<24-hex-id>/image.png|jpg` reads only the configured publication's validated owned raster bytes. The browser session is checked before storage access; missing/foreign/invalid images return no data. Responses are no-store/nosniff with a restrictive image CSP. Rich text displays this route only for same-origin CMS image references; the stored source keeps the original content URLs. It does not fetch arbitrary remote URLs or transfer image bytes into stored HTML. The public image route still requires an eligible published reference; withdrawal makes anonymous reads404.

Actual iA8.0.9 created a synthetic draft and opened the generic CMS route. Actual Safari login, save and explicit local publication succeeded after two evidenced fixes: same-origin referrer policy preserves Origin on native forms, and fetch uses `form.getAttribute('action')` because submit buttons named action shadow the form property. Local authenticated API withdrawal returned the post/image to private404 state.

The subsequent two-mode editor, since replaced, was tested in a hidden WebKit browser without changing native Safari focus: owned image loaded, headings/link/lists/table rendered, unchanged mode round-trip was exact, unsupported style markup remained intact in HTML, rich edit/save succeeded, a competing tab received409 with its edits retained, and explicit publication succeeded. The synthetic post was then withdrawn and anonymous content/image reads both returned404. Separate real PostgreSQL review integration and Go race regressions passed. This does not claim automatic native iA image upload: observed local-file markup was sent without bytes, and no upload request was observed. A documented Library Content Block trial omitted the unlinked file. Ulysses remains unverified.

## Editor replacement, 2026-10-26

The homemade `execCommand` editor was replaced at the user's request. Undo history now survives mode switches and successful saves. The server's auth, CSRF, optimistic concurrency, revision/outbox and explicit publication contracts are unchanged.

Evidence: 43 conversion cases and 9 page scenarios pass in Google Chrome and in Playwright WebKit 26.6 against the synthetic devserver, and every conversion output passes the real CMS validator. The scenarios cover untouched mode round trips, undo restoring exact source, toolbar and link dialog, save without replacing the editor, undo after save, reload and unsaved-edit warning, a stale second tab receiving 409 with edits kept, an explicit lossy conversion, Markdown saves, tables, paste sanitizing, publish, and a touch viewport with a sticky one-row toolbar and preserved selection. Emulated touch in desktop engines is not a physical iPhone; native iOS Safari, native iA automatic image upload and Ulysses remain unverified.
